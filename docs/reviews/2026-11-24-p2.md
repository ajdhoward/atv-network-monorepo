## Found and fixed here

`pnpm continuity`'s secret rule was one-directional. Rule 3 read the inventory and asked whether each name
still existed in the repository, which catches a rename or a deletion. The failure it could not see is the
one that matters after the account is gone: a secret the Worker started reading last week, named in `env.ts`
and in nobody's inventory, which a rebuild has no way to learn about. The check now reads `env.ts`, takes the
`ATV_*` entries typed `string` (a KV namespace, a Fetcher, a Durable Object namespace or an Analytics Engine
dataset is infrastructure with nothing to recover), and fails when one is missing from the inventory.

It found the four real secrets and they are all inventoried, so the current tree passes; adding
`ATV_TMP_SECRET?: string;` to `env.ts` makes it fail with the name, which is how the new test was checked
rather than assumed. `scripts/lib/docs-check.mjs`, `scripts/check-continuity.mjs` and two tests in
`scripts/test/continuity.test.ts` (one for the missing name, one proving a binding is not demanded).
